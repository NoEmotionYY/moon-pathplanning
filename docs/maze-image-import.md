# 图片迷宫导入设计

本文记录 Moon PathPlanning Web 的栅格图片迷宫导入架构。实现目标是把浏览器安全
解码后的正交矩形迷宫转换为项目现有的 `moon-pathplanning.grid.v1` 文档，并在用户
确认后通过原子事务替换主地图。

## 1. 目标与边界

当前管线支持 PNG、JPEG、WebP 栅格图片，面向主要由水平和垂直墙体构成的正交矩形
迷宫。识别阶段不会修改主地图，也不会自动运行 Planner。

当前不支持：

- SVG、PDF；
- occupancy 栅格；
- 蜂窝或六边形迷宫；
- 主要由斜线构成的迷宫；
- 彩色答案路线自动剥离；
- 任意自由形状墙体；
- 手工补墙、擦墙；
- 超过 60×60 的主地图正式导入。

## 2. 文件验证

文件进入解码器前会统一检查：

- 扩展名和 MIME 是否属于 PNG、JPEG 或 WebP；
- 扩展名与 MIME 是否冲突；
- 文件是否为空；
- 文件是否超过 10 MiB；
- 图片宽、高是否分别超过 8192；
- 总像素是否超过 32,000,000。

SVG 与 PDF 可以被文件类型检测器识别，但本阶段不会进入栅格解码或分析管线。错误以
稳定代码和中文信息返回，界面保留弹窗供用户重新选择。

## 3. 浏览器解码

原始文件由浏览器图片能力解码，不由 Worker 直接解析压缩格式。解码结果统一为：

```ts
interface ImageMatrix {
  width: number
  height: number
  rgba: Uint8ClampedArray
}
```

解码后再次核对实际尺寸和像素数，避免仅依赖文件扩展名、MIME 或声明信息。原始
RGBA 留在主线程用于预览，透明像素在分析阶段按估计背景做 Alpha 合成，不会直接
当作黑墙。

## 4. 图片变换

用户可以在识别前执行：

- 左转或右转 90°；
- 水平翻转；
- 垂直翻转；
- 反色；
- 恢复原始状态。

开始分析时会固定一份 transform snapshot。分析服务总是创建新的 RGBA 数组，不修改
预览持有的原始 `ImageMatrix`。分析过程中改变文件或变换会使旧结果失效。

## 5. 图像预处理

预处理依次处理：

1. Alpha 与背景估计；
2. 灰度计算；
3. 深墙/浅墙极性判断；
4. 墙体二值掩码；
5. 去噪和裁剪；
6. 裁剪掩码对应的积分图。

纯白、纯黑等没有足够前景/背景对比的图片会被明确拒绝。裁剪使用稳定前景证据，避免
少量孤立噪点把范围扩张到整张图片。积分图区域采样统一使用半开区间
`[start, end)`。

## 6. 正交结构检测

正交检测从水平和垂直投影中估计：

- 墙线中心；
- 墙体厚度；
- 相邻墙线 pitch；
- 行数与列数；
- 轴向覆盖率和规则度；
- 正交证据与总体置信度。

检测成立时，每个轴必须满足“格线数量 = 单元格数量 + 1”。候选 pitch 会同时检查
真实间距及其半倍、双倍混淆，外框证据不足以单独推断内部网格。蜂窝、六边形或斜线
主体图片会落入低置信度或 `unsupported-topology`，不会生成伪造的正交地图。

## 7. 拓扑分析

在检测出的格线上，对每个逻辑单元格的四条边采样墙体带。内部边界只计算一次，并
同时写入相邻单元格的邻接关系。分析结果包括：

- 水平和垂直内部边界；
- 外边界；
- 开放通道；
- 不确定边界；
- 连通分量；
- 墙体/通道/不确定比例；
- 拓扑置信度与警告。

转换前会验证全部可通行逻辑格的连通性，并拒绝与检测结果不一致的边界或入口。

## 8. 入口候选

入口提取只检查外边界上的开放区段，并记录：

- 所在边（top、right、bottom、left）；
- 起始与结束单元格；
- 宽度；
- 置信度；
- 连通分量；
- reliable、uncertain 等状态。

双入口且配对证据充分时可以自动选择起点与终点。只有一个入口、存在多个候选或配对
证据不足时，结果会进入 `manual-input-required`，保留诊断和候选供界面处理。

## 9. 手动入口 Pair

界面允许用户从候选中分别选择起点和终点、清除选择、交换方向。两个角色不能指向
同一候选。低置信度候选需要额外确认。

手动 Pair 会连同原 transform snapshot 重新发送给 Maze Import Worker；Worker 重新
执行转换和文档校验，不由 UI 拼接或篡改转换结果。成功后记录入口来源为 manual，并
允许继续交换已应用的起终点。

## 10. 2n+1 网格转换

逻辑迷宫的行列数为 `rows × columns`，转换后的地图尺寸为：

```text
width  = columns × 2 + 1
height = rows × 2 + 1
```

逻辑单元格中心映射为：

```text
cell(row, column)
→ (column × 2 + 1, row × 2 + 1)
```

水平相邻单元格的通道映射为：

```text
(leftColumn × 2 + 2, row × 2 + 1)
```

垂直相邻单元格的通道映射为：

```text
(column × 2 + 1, topRow × 2 + 2)
```

其余位置写为障碍物。入口候选映射到对应外边界通道，最终文档使用四方向移动且不
创建虚假 terrain cost。

## 11. Worker 协议

主线程只向 Worker 发送已解码的 `ImageMatrix`。为保留原图预览，客户端先对 RGBA
创建一次 Worker 专用副本，再 transfer 该副本的 `ArrayBuffer`。

请求包含：

- `requestId`；
- 图片宽、高和 RGBA；
- 管线选项与 transform snapshot；
- `summary`、`preview` 或 `full` 结果级别。

界面默认请求 `preview`。该结果包含 Canvas 渲染所需的压缩结构摘要，不返回完整积分
图等大型中间数据。进度保持单调递增。

同步 CPU 分析无法保证及时处理软取消消息，因此客户端取消时会 `terminate()` 当前
Worker。新 Worker 使用新的 `workerGeneration`；客户端同时校验 generation 和
`requestId`，拒绝旧 Worker 的 progress、completed 或 failed 消息。

## 12. 结果预览

预览由 Canvas 绘制，不把大尺寸结果逐格挂载到主地图 DOM。结构预览可显示墙体、
通道、不确定边界、入口候选、起点和终点；地图预览显示转换后的 2n+1 障碍布局。

诊断摘要包含源图片尺寸、变换尺寸、裁剪范围、逻辑行列、转换尺寸、结构/拓扑
置信度、入口状态、障碍格和可通行格数量。预览阶段不会调用 Planner。

## 13. 原子地图导入

用户确认后，图片、JSON 文件和内置示例地图都进入同一个
`applyMapDocumentTransaction`：

```text
校验 GridMapDocument
→ 检查预期 mapVersion
→ 检查正式尺寸能力
→ 捕获 Grid / Planner 快照
→ 阻止新 Planner 请求
→ 硬取消旧 Planner
→ 使旧 requestId 失效
→ 停止 Trace RAF
→ 批量替换地图
→ 清理 Path、Trace 和播放状态
→ 后置条件检查
→ 成功或回滚
```

成功时 `mapVersion` 只增加一次，Planner 状态为 idle，Path/Trace 为空，并默认保留
算法选择和回放倍速。导入后不会自动运行规划。

如果后置阶段失败，事务恢复 Grid 和 Planner 快照，并返回
`MAP_IMPORT_TRANSACTION_ROLLED_BACK`。已经硬取消的旧规划不会重新启动；其迟到消息
也会因 request、version 或 algorithm 不匹配而被拒绝。

## 14. 尺寸限制

| 环节 | 限制 |
|---|---|
| 文件大小 | PNG/JPEG/WebP 最大 10 MiB |
| 解码宽度 | 最大 8192 |
| 解码高度 | 最大 8192 |
| 解码总像素 | 最大 32,000,000 |
| 转换与 Canvas 预览 | 最大 151×151 |
| 主地图正式导入 | 最大 60×60 |

75×75 逻辑迷宫会转换为 151×151，仍可完成识别和 Canvas 预览；76×76 会转换为
153×153，因此在转换硬上限处拒绝。

29×29 逻辑迷宫会转换为 59×59，可以正式导入。30×30 会转换为 61×61，分析结果
仍可预览，但导入能力检查返回 `MAP_IMPORT_RENDER_LIMIT_EXCEEDED`。主地图目前逐格
渲染 DOM，因此 151×151 不是可正式编辑尺寸。

## 15. 错误状态

管线状态：

| 状态 | 含义与 UI 行为 |
|---|---|
| `manual-input-required` | 保留结构预览和入口候选，要求用户选择入口 Pair |
| `unsupported-topology` | 显示不支持的拓扑及诊断，不开放正式导入 |
| `failed` | 显示结构化错误和已完成阶段，允许返回调整或重新识别 |
| `cancelled` | 回到可选择/调整状态，不应用任何地图 |

地图事务错误：

| 错误码 | UI 行为 |
|---|---|
| `MAP_IMPORT_STALE_PREVIEW` | 当前地图已变化，禁止旧预览覆盖新修改，要求重新识别或重新选择 |
| `MAP_IMPORT_RENDER_LIMIT_EXCEEDED` | 保留分析预览，禁用正式导入 |
| `MAP_IMPORT_TRANSACTION_BUSY` | 保留当前内容，提示等待另一项事务完成 |
| `MAP_IMPORT_TRANSACTION_ROLLED_BACK` | 提示原地图已恢复，旧 Planner 已取消 |

JSON 导入另有文件类型、大小、读取、解析和文档格式错误。所有失败都不会触发成功
Toast 或导入成功事件。

## 16. 性能数据

开发机器上的自动化测试已验证 75×75 逻辑迷宫：

- 转换结果为 151×151；
- Worker 完整分析通常为数百毫秒量级；
- 分析在独立 Worker 中进行，主线程保持可交互；
- 因主地图 60×60 正式限制，确认导入操作被禁用。

这些数据用于回归观察，不是跨浏览器、跨设备的固定性能保证。测试不使用依赖机器
速度的硬耗时阈值。

## 17. 测试策略

Vitest 覆盖：

- PNG/JPEG/WebP 文件验证、安全解码、透明背景和图片变换；
- 5×5、8×10、20×20 与 1/3/5 像素墙宽；
- pitch 半倍/双倍混淆、单外框、蜂窝和斜线反例；
- 拓扑、内部/外部边界、入口候选、手动 Pair 和方向交换；
- 2n+1 坐标、59×59/61×61/151×151 尺寸边界；
- Worker 协议、transfer、hard cancel、generation 和迟到消息隔离；
- 图片、JSON、示例地图的事务成功、stale、busy、rollback；
- 真实 Pinia 下的 mapVersion、Path、Trace、Planner 和偏好状态；
- 弹窗状态、确认流程和图片导入回归。

完整命令见[根 README](../README.md)和
[Web README](../web/README.md)。

## 18. 后续路线

后续可独立评估 SVG/PDF 解码、occupancy、手工墙体修正、Canvas 主地图和更多拓扑；
这些能力不属于当前实现。扩展正式地图尺寸前，需要先替换主地图逐格 DOM 渲染并重新
验证编辑、Planner、Trace 与移动端性能。
